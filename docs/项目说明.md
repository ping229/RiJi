## 1. 这是什么

一个**个人日记平台**：本地优先、多端同步、媒体（图片/语音/视频）内联在正文里、端到端加密、可多节点部署。

- 客户端：Flutter（Windows + Android），同一份代码
- 服务端：Node 22 + TypeScript + Fastify + PostgreSQL
- 管理后台：原生 JS 单页，由服务端直接托管在 `/admin`
- 部署：Windows 一键安装 / Linux 原生脚本 / Docker Compose（后两者未实测）

**当前状态**：Windows 端实测可用；安卓包已构建但未真机验证；VPS 已上线。

## 3. 怎么跑起来

### 3.1 本机开发

```powershell
# 1. 数据库（独立实例，端口 5544，不影响系统 5432）
pwsh -File tools/dev-db.ps1 -Action start

# 2. 服务端
cd server
npm install
npm run migrate                 # 建表
npm start                       # 默认 8080

# 3. 客户端
cd client
flutter run -d windows
```

首次启动会自动创建管理员，密码写在 `server/var/admin-initial-password.txt`。

### 3.2 一键安装（给最终用户）

双击根目录 `安装.bat`：检查环境 → 准备数据库 → 装依赖 → 建表 → 启动 → 建桌面快捷方式。幂等，可重复执行。

### 3.3 VPS

已部署的机器见 [VPS部署记录.md](VPS部署记录.md)（地址、路径、账号、运维命令）。
重新部署：打包 `server + admin` → 上传 → 解压到 `/opt/riji` → `npm install` → `systemctl restart riji`。

## 4. 架构总览

```
 Flutter 客户端（多设备）
   │  HTTPS/HTTP + JWT
   ▼
 节点 A（primary）──── 复制（mTLS 可选）──── 节点 B（replica）
   │  事务写                          │  追增量 + 回填媒体
   ▼                                  ▼
 PostgreSQL                         PostgreSQL
（业务数据 + 复制日志 + 媒体元数据）
   │
   └── 媒体文件：磁盘（默认 server/var/media，VPS 为 /var/lib/riji/media）
```

**本地优先**：客户端写操作先落本地（缓存 + 待推送队列），再异步推送服务器。
断网可写，联网后自动补推；拉取时以服务器为准合并。

**加密边界**：客户端加解密，服务端只存密文。服务端**永远不需要**密钥。

## 5. 数据模型（核心表）

| 表 | 作用 | 关键字段 |
|---|---|---|
| `users` | 账号 | `password_hash/salt`、`role`、`kdf_salt`、`kdf_iterations`、`key_wrap`（主密钥包裹体）、`recovery_wrap/proof`（恢复短语）、`quota_bytes` |
| `devices` | 设备 | `user_id`、`name`、`platform` |
| `diaries` | 一天一篇 | `UNIQUE(user_id, diary_date)`、`vv`、`time_suspect` |
| `blocks` | 块序列 | `diary_id`、`block_type`(text/image/audio/video/divider)、`order_key`（小数排序键）、`payload`(bytea 密文)、`enc`、`nonce`、`media_ref`、`vv`、`hlc`、`tombstone` |
| `block_versions` | 冲突落败版本 | `block_id`、`payload`、`hlc`，保留 30 天 |
| `media` | 媒体元数据 | `user_id+media_key` 唯一、`byte_size`、`mime`、`enc`、`nonce`、`blob_path` |
| `media_jobs` | 媒体转码队列 | `status`(pending/processing/done/skipped/failed) |
| `replication_log` | 复制日志 | 自增 `seq`、`entity`(user/diary/block)、`op`、`payload` |
| `replication_state` | 副本游标 | `node_id`、`cursor` |
| `nodes` | 集群节点 | `role`、`status`、`replication_lag`、`full_sync_requested_at` |
| `refresh_tokens` | 刷新令牌 | 可整体吊销（改密码时） |
| `audit_log` | 审计 | 所有敏感操作 |

**为什么 payload 是 bytea**：密文是任意字节，不能当 text 存。

## 6. 关键机制（改代码前必须懂）

### 6.1 业务日与时间窗口

- 每天 04:00 为日切点：凌晨 3 点写的东西算"前一天"。
- 可写窗口 `[今天-7, 今天]`，共 8 天；**未来日期一律拒绝**。
- 窗口外只读：客户端不显示编辑控件，服务端也拒绝写入（`422`/`400`）。
- 实现：`domain/calendar.ts`（服务端）、`core/diary_date.dart`（客户端），两边必须一致。

### 6.2 冲突：版本向量 + HLC

- 每个设备维护自己的版本向量（VV）计数。
- 每次写带一个 HLC（混合逻辑时钟）字符串，`(物理毫秒, 计数, 设备)`，字典序即时间序。
- 服务端仲裁：
  - 新 VV 支配旧 VV → 正常覆盖
  - 并发（互不支配）→ **HLC 较大者胜**，落败版本写入 `block_versions`
- 客户端可以在"版本历史"里查看并一键恢复落败版本。

### 6.3 端到端加密（重点）

三层密钥：

```
密码 + 盐 ──PBKDF2(21万次)──▶ KEK
                              │ 解开
                              ▼
                         主密钥 M（32B，客户端内存/会话文件）
                              │
                    ┌─────────┴─────────┐
               块内容 AES-GCM        媒体 AES-GCM
               AAD=blockId|hlc       AAD=media|mediaKey
```

- 服务端存 `key_wrap = E(KEK, M)`；改密码 = 用新 KEK 重新包裹 M，**历史数据不用重加密**。
- 恢复短语：16 个英文单词（128 bit）→ 哈希扩展出"恢复密钥" → 用它再包裹一份 M（`recovery_wrap`），并存 `recovery_proof = SHA256(seed)` 作为持有证明。
- 服务端**没有任何**能解开数据的密钥。

**红线**：
1. 不要在任何服务端日志/接口里输出 payload 明文。
2. 不要在服务端做"搜索日记内容"——服务端搜不了，也没必要。
3. 媒体上传前加密；服务端转码必须跳过加密媒体（已实现）。

### 6.4 媒体流水线

```
选择/拍摄 → 图片压缩(长边2048) → 可选加密 → 上传(内容哈希为 key)
   → 本地缓存明文（供播放/导出）→ 使用时按需下载并解密
```

- 去重：`HEAD /api/media/:key` 已存在则跳过上传。
- 转码队列：仅主节点、仅有 ffmpeg 时、且**非加密**媒体才转码；失败只记录，不动原文件。
- 导出必须解密：`ExportService` 走 `MediaService.bytesFor` 或自带解密（曾有 bug：直接 `downloadMedia` 拿到密文，已修）。

### 6.5 多节点复制

- 主节点每次业务写都追加 `replication_log`（与业务写同事务）。
- 副本轮询 `GET /api/replication/log?since=cursor`，幂等重放。
- 首次启动或全量同步时：基线快照（用户→日记→块→**历史版本**→媒体元数据）+ 媒体回填。
- 后台"全量同步"：主节点只记 `full_sync_requested_at`，副本下次心跳读到后把游标清零重放。
- 节点间可用 mTLS（`RJJ_TLS_DIR`，9443），未启用时用共享令牌。

**复制载荷里必须有这几样东西**（少一样副本就会坏）：

| 字段 | 少了会怎样 |
|---|---|
| `kdfSalt / keyWrap / keyWrapNonce / recovery*` | 副本上的账号登录时以为"没启用加密"，生成新密钥并覆盖包裹体 → 老日记永久解不开 |
| `media.nonce` | 副本上加密媒体解不开（客户端会把密文当明文） |
| `block_versions` | 副本接管后"版本历史"是空的 |
| `quota_bytes` | 副本上配额显示成"不限制" |

副本仲裁与主节点用**同一套规则**（`shouldApplyBlock`）：版本向量支配才覆盖，并发按 HLC 比。
只按 HLC 会让两边选出不同赢家。

副本升级后如果数据是旧的，去后台点一次「全量同步」，再重启副本即可补齐；
启动时还会自动跑一次 `repairMediaMetadata` 修 nonce。

### 6.6 存储配额

- `users.quota_bytes`，默认 5GB（`RJJ_DEFAULT_QUOTA_GB`），`NULL`/0 = 不限制。
- 只统计 `media` 表字节数（文字体积可忽略）。
- 检查在媒体写入事务内、并对用户行 `FOR UPDATE`，避免并发绕过。
- 超限返回 `413 QUOTA_EXCEEDED`，消息里带"已用/配额/本次需要/还差"。

### 6.7 AI 总结

- 客户端实现，兼容 OpenAI `/chat/completions`。
- 配置（地址/Key/模型/图片上限）存本机 `ai-settings.json`，不上传服务器。
- 发送内容：带日期的日记文本；可选附带图片（base64 `image_url`，长边 1024）。
- 图片超上限时**均匀抽样**（不是取前 N 张）。
- 模型不支持图片 → 自动退回纯文本重试一次，并在结果上方提示。
- 音频：仅 wav/mp3 会附带（当前录音是 m4a，暂不发）；视频不发。

## 8. 客户端结构（`client/lib`）

| 文件 | 职责 |
|---|---|
| `main.dart` | 启动、会话恢复、主题、按账号打开本地库 |
| `core/api_client.dart` | 所有 HTTP，统一错误 → `ApiException` |
| `core/local_store.dart` | 本地缓存（按账号分目录）、待推送队列、媒体缓存 |
| `core/sync_service.dart` | 推送/拉取、加解密块（**加密边界在这里**） |
| `core/crypto_service.dart` | PBKDF2/AES-GCM、包裹与解包 |
| `core/recovery_service.dart` + `recovery_phrase.dart` | 恢复短语生成与恢复 |
| `core/media_service.dart` | 上传（压缩/加密/去重）、下载解密、播放文件落盘 |
| `core/export_service.dart` | 四种导出（HTML/MD/PDF/ZIP）+ 取消 + 解密媒体 |
| `core/rich_text.dart` | 富文本标记解析（标题/列表/引用/代码/粗斜体/链接） |
| `core/search_service.dart` | 本地全文搜索（服务端搜不了） |
| `core/calendar_grid.dart` | 日历网格计算（纯函数，可测） |
| `core/diagnostics.dart` | 自检项（连通/登录/加密/同步/缓存/存储/字体） |
| `core/error_messages.dart` | 异常 → 人话（含权限引导） |
| `ui/` | 登录、主页、编辑器、日历、搜索、自检、AI 总结、摄像头 |

**本地缓存目录**（重要）：`<数据目录>/diary_<账号>/`，内有 `diaries/`、`media/`、`outbox.json`、`owner.txt`。
数据目录优先级：`%APPDATA%\RiJi` → `%LOCALAPPDATA%\RiJi` → 系统推荐目录 → exe 同级 `data/`。
**换账号必须换目录**（否则会看到别人的日记——这是修过的 bug，别再退回去）。

## 10. 已知问题 / 未验证 / 待办

**未验证**：

- 安卓真机（APK 已构建、插件已注册，但没在手机上跑过）
- Docker 镜像构建（本机 Docker 无 WSL 发行版）
- Linux 原生部署脚本（无 Linux 主机）
- Windows 摄像头实际画面（受系统隐私设置限制）

**已知限制**：

- 删除日记只做墓碑，**不释放磁盘**；配额按现存媒体算
- 语音块发不到 AI（m4a 不在多数接口支持列表）
- 视频不能发给 AI
- 本地缓存是明文（服务端才是密文）
- 冲突 UI 只有版本历史，没有逐字 diff

**已知环境坑（会反复踩）**：

1. **Windows 构建**：`video_player_win` 插件会调 nuget 下载 WIL。已把包放在 `tools/wil-package/wil.nupkg`；`flutter clean` 后需要重新解压到 `client/build/windows/x64/packages/Microsoft.Windows.ImplementationLibrary/` 再构建。换过 pub 镜像后，**新的缓存副本没有补丁**，需要把打补丁的 `CMakeLists.txt` 复制过去（补丁内容：检测 `packages/.../targets` 存在就跳过 nuget）。
2. **pub 镜像**：`pub.flutter-io.cn` 对 camera 系列包返回 525；用 `https://mirrors.tuna.tsinghua.edu.cn/dart-pub` 可解。
3. **PowerShell 写中文/换行**：这里字符串里的 `` `r`n `` 在单引号中是字面量，会写进文件造成 `\`r\`n` 垃圾（管理员页曾出现）。改代码优先用 `edit` 工具或 here-string。
4. **Dart AOT 字符串检查**：搜二进制里的中文要**奇偶两个偏移**都试，UTF-16 可能从奇数字节开始。
5. **npm 在 PowerShell**：用 `npm.cmd`，`& npm` 会被解析成 `npm.ps1` 导致参数错乱。

## 11. 改代码时的红线

1. **管理员不可见日记内容**：任何管理接口都不能返回 payload/媒体内容。
2. **加密边界在客户端**：`sync_service` 是唯一加解密处；别在服务端加"帮我解密"的能力。
3. **本地缓存必须按账号隔离**（`LocalStore.open(baseDir, account: ...)`）。
4. **导出/播放/查看原图都必须走解密路径**（`MediaService`），不要直接 `api.downloadMedia`。
5. **时间窗口规则**两边一致，改一处必须改另一处。
6. **媒体转码必须跳过加密媒体**。
7. 迁移**只增不改**；改结构请新增 `00xx_xxx.sql`。
8. **复制用户的 SQL 必须用 `toUserLogPayload`**（`services/replication.ts`），不要手写映射——漏字段就是丢密钥。
9. **保存分两段**：`_persistLocal`（0.6 秒防抖，写缓存+outbox）与 `_syncNow`（退出/手动/空闲才推）。
   别把网络请求塞回输入回调，否则又会变成"每敲几个字推一次"。
