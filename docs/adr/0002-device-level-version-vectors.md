# ADR-0002：版本向量以设备为维度，而非节点

- 状态：已采纳
- 日期：2026-11-04

## 背景

需求 4.2(A) 写的是"每个节点维护 `{node_id → counter}` 的版本向量"。
但平台明确采用主从复制（4.1）：所有写入都先到主节点，副本只接收推送。
如果版本向量只按节点计数，那么同一用户的两台设备先后写入都会被计成同一个维度，
**永远检测不出并发冲突**——这正是产品红线"同步不静默丢数据"要防的情况。

## 决策

版本向量的维度使用 **device_id**（客户端设备），而不是 node_id。

- 每台设备维护自己的计数器，提交块时带 `vv = { 自身设备: n, 见过的其他设备: m, ... }`。
- 服务端比较版本向量判断因果与并发，仲裁规则不变。
- 服务端节点的身份只用于复制链路与拓扑，不进入版本向量。

## 后果

- 同一用户多设备的并发修改能被正确识别为 `concurrent`，进入冲突流程。
- 设备数量上限即向量维度上限；实际个人日用场景远低于任何阈值。
- 与需求 4.2 的字面表述有差异，需在架构文档中说明理由（本 ADR 即说明）。
