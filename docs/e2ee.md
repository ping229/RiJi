# 端到端加密说明

对应需求 6.1 / 10.7。这份文档说明**加密到什么程度、保护什么、不保护什么**。

## 一句话

服务端与所有节点只存密文；密钥由你的密码在**你自己的设备上**派生，从不上传。
管理员、节点运维方、数据库备份都无法读出日记内容。

## 密钥是怎么来的

```
密码 + 随机盐（服务端存，不是秘密）
        │  PBKDF2-HMAC-SHA256，21 万次迭代
        ▼
      KEK（密钥加密密钥，只在客户端出现片刻）
        │  解开服务端存的"主密钥包裹体"
        ▼
   主密钥（32 字节，真正加密数据的那把）
        │
        ├─ AES-256-GCM（每个块独立 nonce）
        │     用于日记正文块
        └─ AES-256-GCM（媒体独立 nonce）
              用于图片 / 语音 / 视频
```

**为什么多一层**：如果主密钥直接等于"密码派生结果"，用户一改密码，历史数据就永久解不开了。
现在密码只负责解开包裹体，主密钥本身不变——改密码只是"用新 KEK 重新包裹同一把钥匙"，
历史数据完全不用动。

| 场景 | 结果 |
|---|---|
| 改密码 | 旧密码解开主密钥 → 新 KEK 重新包裹 → 历史数据照常可读 |
| 新设备登录 | 拉取包裹体 → 用密码派生的 KEK 解开 → 得到同一把主密钥 |
| 服务端被入侵 | 只有包裹体，没有 KEK，解不开 |
| 忘记密码 | 用恢复短语可以找回；**既没设短语又忘了密码 = 永久丢失** |

- 盐在**首次登录时由客户端随机生成**并提交给服务端保存，服务端不接受覆盖。
- 同一账号在任何设备上用同一密码登录，会派生出同一把主密钥——这是多设备能互相解密的前提。
- 主密钥保存在客户端的会话文件里（`%APPDATA%\com.riji\riji_client\session.json`），所以重启后不用重新输密码。

## 密文长什么样

数据库中一条加密块的实测形态：

```
payload(hex) 0e970f00957fb9c68e60bdde9b1b01258e8932e1f8a...
长度         92 字节（76 字节明文 + 16 字节 GCM 认证标签）
enc          aes-256-gcm
nonce        b87cde80cee2816b4208971e
```

把 payload 当文本读会直接报错：

```
ERROR: invalid byte sequence for encoding "UTF8": 0x97
```

而升级前未加密的历史数据仍然可读（`enc='none'`），两者可以共存。

## 防篡改

每个块的密文都用 AAD 绑定自身身份：

```
AAD = blockId | hlc
```

如果有人把 A 块的密文挪到 B 块，或改动块 ID/时钟，解密会直接失败。
实测：篡改块 ID 后解密被拒（✓）。

## 保护什么 / 不保护什么

| 场景 | 是否受保护 |
|---|---|
| 云主机被入侵，攻击者拿到数据库 | ✅ 只有密文 |
| 管理员用后台或数据库偷看 | ✅ 看不到（接口层也没有入口） |
| 数据库备份被拖走 | ✅ 只有密文 |
| 节点运维方读取磁盘 | ✅ 只有密文 |
| **你的电脑 unlocked 时被他人使用** | ❌ 客户端能自动解密 |
| **本机磁盘被拆走** | ❌ 本地缓存是明文 |
| **忘记密码且丢失所有设备** | ❌ 数据永久无法解密（E2EE 的固有代价） |

本地缓存刻意保留明文：离线可用、导出、播放都依赖它。如果把它也加密，
每次启动都要输密码，且导出流程要重做。这个取舍可以改，但需要重新设计启动流程。

## 尚未实现（诚实说明）

| 项 | 说明 |
|---|---|
| 多设备密钥传递 | ✅ 通过"服务端存包裹体 + 密码派生 KEK"实现 |
| 恢复短语 | ✅ 16 个词，忘记密码可用它重置并保住历史数据 |
| 主密钥轮换 | 未实现。改密码只换包裹层（客户端菜单「修改密码」），主密钥本身不变 |
| 设备撤销 | 未实现 |
| 媒体密钥与正文密钥分离 | 目前共用一把主密钥，仅 nonce 与 AAD 不同 |

这些属于需求 6.1 里的"多设备密钥同步"部分，是后续版本的工作。

## 怎么自己验证

```powershell
cd server
npm run migrate            # 确保 0004_e2ee.sql 已应用

cd ..\client
set RJJ_PASS=你的密码
dart run tool/e2ee_probe.dart
```

探针会写一条加密日记、读回解密、并验证篡改会被拒绝。
然后用 psql 查 `blocks.payload`，你会看到二进制乱码而不是中文。

## 恢复短语

16 个英文单词，128 bit 熵，只显示一次。它对应的是一把独立的「恢复密钥」，
服务端存着「用恢复密钥包裹的主密钥」和「恢复密钥的散列」，两样都解不开主密钥。

忘记密码时：

1. 登录页点「忘记密码？用恢复短语找回」
2. 输入用户名、16 个词、新密码
3. 客户端用短语还原恢复密钥 → 解出主密钥 → 用新密码派生的 KEK 重新包裹 → 提交
4. 旧密码立刻失效，历史日记照常可读

实测（真实服务器，一次性账号）：

```
3. 恢复短语：deny king bank cold date camp grow mass hole gave loss debt bill edge gold boat
5. 已用短语恢复，新密码设置完成
7. 新密码解出的主密钥与恢复时一致：✓
8. 解密历史日记：{"text":"恢复前的日记内容"}
9. 旧密码已失效：✓
```

**没设恢复短语又忘了密码 = 数据永久丢失。** 这是端到端加密的固有代价，产品里必须明确告知。
## 媒体转码与加密的关系

服务端有一个媒体归一化队列（把 .mov/.webm/.wav 转成 H.264/AAC）。但它有一条硬规则：

> **已加密的媒体一律跳过转码。**

原因很简单：加密后的文件在服务器磁盘上是密文，ffmpeg 读到的是一堆随机字节，
强行转码只会把文件毁掉。实测确认：

```
上传加密的 .mov → status=skipped
reason=媒体已端到端加密，服务端无法转码（需要保留原始格式）
下载大小 2997（原始 2997）→ 未被改动 ✓
```

代价是：启用加密后，跨平台播放依赖客户端上传时的编码。我们自己的录音/录像路径
（Windows 与安卓都用 AAC/H.264）本来就是兼容的，所以日常使用没有影响。
真正需要归一化的是用户自己导入的第三方视频——这类文件建议在导入前自行转换。
