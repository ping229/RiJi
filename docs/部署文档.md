# 部署文档（给不懂开发的负责人）

这份文档假设你从来没有装过这个项目。照着从上往下做，每一步都告诉你**应该看到什么**。
如果某一步的结果和"预期结果"不一样，停在那一步，按第 9 章的对应条目处理。

> 说明：本文档描述的是**本项目实际交付并验证过**的部署方式（Windows 单机 / 双节点）。
> Linux + Docker 的部署方式在附录里有说明，但**尚未在本项目中实际验证**，不能照做上线。

---

## 1. 你需要准备什么

| 项目 | 要求 | 怎么确认 |
|---|---|---|
| 一台 Windows 电脑 | Windows 10 或 11 | 能正常开机、能上网 |
| 磁盘空间 | 至少 5 GB 空闲 | 打开"此电脑"看 C 盘 |
| Node.js | 18 或更高 | 安装后在命令行输入 `node --version`，显示 `v22.x` 之类 |
| PostgreSQL | 15 或更高 | 安装后 `C:\Program Files\PostgreSQL\17\bin\pg_ctl.exe` 存在 |

两个软件都是免费的：

- Node.js：<https://nodejs.org/zh-cn> —— 下载 LTS 版本，一路"下一步"。
- PostgreSQL：<https://www.postgresql.org/download/windows/> —— 安装时设的密码**自己记下来**（本程序用不到它，但将来卸载/修复要用）。

> **不需要**懂数据库，也**不需要**手动建库建表，安装脚本会自己处理。

## 2. 安装

1. 把整个 `RiJi` 文件夹放到一个**路径里没有空格**的位置，例如 `D:\RiJi`。
2. 双击文件夹里的 **`安装.bat`**。
3. 会弹出一个黑色窗口，自动做六件事，每件都会打勾。

**预期结果**（全部通过时会看到）：

```
[1/6] 检查运行环境
  ✓ Node.js v22.19.0
  ✓ PostgreSQL（C:\Program Files\PostgreSQL\17\bin）

[2/6] 准备数据库（独立实例，不影响系统里已有的数据库）
  ✓ 数据库已启动（端口 5544）
  ✓ 已创建数据库 riji

[3/6] 安装服务端依赖（首次约需 1 分钟）
  ✓ 依赖已安装

[4/6] 初始化数据表
  ✓ 数据表已就绪

[5/6] 启动服务端
  ✓ 服务端已启动

[6/6] 创建桌面快捷方式
  ✓ 桌面已创建「日记」快捷方式
```

4. 最后它会问"现在打开管理后台看看？"，按回车即可。

> 安装脚本可以重复运行，不会弄丢已有数据。搬家、重装、修环境时都可以再跑一次。

## 3. 四个检查点（确认真的装好了）

### 检查点 1：服务端活着

浏览器打开 <http://127.0.0.1:8080/healthz>

**预期结果**：看到一行类似这样的内容

```json
{"status":"ok","nodeId":"node-local","role":"primary","time":"2026-08-01T10:00:00.000Z"}
```

如果页面打不开，看第 9 章"服务端起不来"。

### 检查点 2：管理后台能登录

浏览器打开 <http://127.0.0.1:8080/admin>

**预期结果**：看到一个居中的登录卡片，标题是"日记平台"。

用安装时打印的管理员账号密码登录（密码也写在 `server\var\admin-initial-password.txt`）。

登录后**预期结果**：左侧有"概览 / 用户管理 / 节点管理 / 审计日志"四个菜单，右侧显示用户数、日记数、媒体容量等卡片。

### 检查点 3：客户端能打开

双击桌面上的「日记」图标。

**预期结果**：出现一个窗口，标题栏写"日记"，中间是登录框，服务器地址已经填好 `http://127.0.0.1:8080`，下面显示绿色"服务器可连接"。

输入同样的账号密码登录。

**预期结果**：进入主页，看到"可写窗口"（今天和往前 7 天）和"最近日记"。

### 检查点 4：能写一篇日记

1. 点右下角"写今天"。
2. 在正文里打几个字。
3. 等 1 秒多，右上角状态从"保存中…"变成"已保存 HH:MM"。
4. 点返回箭头回到主页。

**预期结果**：主页"今天"那张卡片上出现"1 个块"。

## 4. 日常使用

### 写日记

- 主页点某一天，或点"写今天"。
- 工具栏四个按钮：**文字 / 图片 / 语音 / 视频**。
- 图片会从电脑里选；语音会直接调用麦克风录；视频从电脑里选。
- 停止输入约 1.2 秒自动保存，不需要点"保存"。

### 补写与只读

- 今天和往前 7 天都可以写，共 8 天。
- 超过 7 天的日记会锁定为只读，打开时顶部会有提示条。
- 凌晨 4 点算作"新的一天"的开始（深夜写到 4 点前仍算前一天）。

### 导出

右上角菜单 → 选格式 → 选一个文件夹 → 等进度条走完 → 完成后可点"打开文件夹"。

| 格式 | 什么时候用 |
|---|---|
| HTML 包 | 想做一份双击就能读、媒体能直接播放的备份 |
| Markdown 包 | 想导入 Obsidian / Typora 等笔记软件 |
| PDF | 想打印或交给别人看（音视频只有占位说明） |
| 归档 ZIP | 长期存档、换平台、找技术同学排查问题 |

> 导出的是**明文**文件，不再受平台保护。别放在公共网盘或共享目录里。

### 管理后台

- 用户管理：给家人朋友开账号、禁用、删除。
- 节点管理：加第二台机器、退役节点。
- 审计日志：谁在什么时候做了什么。

**注意**：管理员能看到用户数量和状态，**看不到任何日记内容**，也不能导出别人的日记。这是设计上的硬限制，不是还没做。

## 5. 加第二台电脑（多节点，可选）

目标：即使一台机器坏了，另一台也有完整数据。

### 在被加入的那台机器上

1. 装好 Node.js 和 PostgreSQL（同上）。
2. 把 `RiJi` 文件夹复制过去（或从第一台机器的共享目录拷）。
3. 用记事本打开 `tools\启动日记.bat`，找到设置环境变量的地方，改成：

```bat
set RJJ_PORT=8081
set RJJ_NODE_ID=node-replica
set RJJ_NODE_ROLE=replica
set RJJ_PRIMARY_URL=http://第一台机器的IP:8080
set RJJ_REPLICATION_TOKEN=和一串你自己定的密码
```

4. 启动后看窗口输出，**预期结果**会依次出现：

```
基线同步完成：3 篇日记、8 个块
基线媒体补齐：3 个文件
[replica] 应用 N 条变更，游标 X/Y
```

### 在第一台机器的管理后台登记

节点管理 → 填写：
- 节点标识：`node-replica`
- 节点地址：`http://第二台机器IP:8081`
- 角色：副本

**预期结果**：列表里出现该节点，状态"在线"，"落后"显示 0。

### 怎么知道真的同步了

在第二台机器上打开客户端（服务器地址填第二台的地址），**预期结果**：能看到和第一台完全一样的日记。

更严格的办法：把第一台关机，第二台仍然能打开、能读。这就是"拔掉一台数据还在"。

## 6. 备份

数据在两个地方：

| 内容 | 位置 |
|---|---|
| 日记、用户、审计 | PostgreSQL 数据目录（默认 `C:\dev\pg-data`） |
| 图片、语音、视频 | `server\var\media`（或环境变量 `RJJ_MEDIA_DIR` 指定的位置） |

### 备份命令（在 server 目录执行）

```powershell
$ts = Get-Date -Format 'yyyyMMdd-HHmm'
& 'C:\Program Files\PostgreSQL\17\bin\pg_dump.exe' -h 127.0.0.1 -p 5544 -U diary -d riji -F c -f "D:\备份\riji-$ts.dump"
Copy-Item -Recurse '.\var\media' "D:\备份\media-$ts"
```

**预期结果**：`D:\备份` 下出现一个 `.dump` 文件和一个 `media-` 开头的文件夹。

### 恢复

```powershell
& 'C:\Program Files\PostgreSQL\17\bin\pg_restore.exe' -h 127.0.0.1 -p 5544 -U diary -d riji --clean --if-exists "D:\备份\riji-20260801-1000.dump"
Copy-Item -Recurse "D:\备份\media-20260801-1000\*" '.\var\media'
```

**预期结果**：重启服务端后，日记和媒体都回来了。

## 7. 升级

1. 停掉服务端（关掉那个黑色窗口，或在任务管理器结束 `node` 进程）。
2. 用新版本的 `server`、`client`、`admin`、`tools` 覆盖旧目录（**不要覆盖** `server\var`，那是你的数据）。
3. 再跑一次 `安装.bat`（它会自动执行数据库升级脚本）。
4. 双击桌面「日记」验证。

**预期结果**：安装脚本第 4 步显示"数据表已就绪"，登录后能看到升级前的日记。

---

## 8. 卸载

1. 关闭服务端和客户端。
2. 删除 `RiJi` 文件夹。
3. 删除 `C:\dev\pg-data`（数据库）与 `%APPDATA%\com.riji`（客户端缓存）。
4. 如果不再用，可以卸载 Node.js 和 PostgreSQL。

**注意**：第 3 步删掉就找不回来了，删之前先按第 6 章备份。

## 9. 常见故障

### 服务端起不来

**现象**：`/healthz` 打不开。
**先看**：`server\var\server.log` 的最后 20 行。
**常见原因**：

| 日志里出现 | 含义 | 怎么办 |
|---|---|---|
| `EADDRINUSE` | 8080 端口被别的程序占了 | 关掉占用程序的，或在启动脚本里改 `RJJ_PORT` |
| `ECONNREFUSED 127.0.0.1:5544` | 数据库没启动 | 跑一次 `tools\dev-db.ps1 -Action start` |
| `password authentication failed` | 数据库用户对不上 | 说明你用的是自己的 PostgreSQL 实例，需改启动脚本里的 `RJJ_DATABASE_URL` |

### 管理员密码忘了

在 `server` 目录打开命令行，执行：

```powershell
npm run set-password -- admin 你的新密码
```

**预期结果**：输出"已重置 admin 的密码，并吊销其全部登录令牌"。用新密码登录即可。

### 客户端打不开 / 一打开就闪退

1. 确认 `dist\RiJi-Windows-x64` 里 `data` 文件夹还在（那是程序的资源，删了就跑不起来）。
2. 换个位置重装：把整个 `RiJi` 放到路径没有空格和中文的盘符根目录再试。

### 客户端连不上服务器

- 检查 `<http://127.0.0.1:8080/healthz>` 是否能打开。
- 如果服务器在另一台机器，地址要填那台机器的**局域网 IP**（如 `http://192.168.1.10:8080`），不是 `127.0.0.1`。

### 手机连不上电脑

手机和电脑要在同一个 Wi-Fi 下，并且：

1. 启动服务端前设 `set RJJ_HOST=0.0.0.0`（默认只听 127.0.0.1）。
2. Windows 防火墙放行 8080 端口。
3. 手机里填电脑的局域网 IP。

### 导出 PDF 中文变成方块

说明没找到系统中文黑体。**预期位置**：`C:\Windows\Fonts\simhei.ttf`。如果被删了，随便装一款中文字体（如思源黑体）后重试。

### 多节点显示"落后"一直不归零

1. 在副本机器上看输出有没有 `[replica]` 报错。
2. 检查两台机器的 `RJJ_REPLICATION_TOKEN` 是否完全一致。
3. 检查副本能否访问主节点的 8080 端口（`RJJ_PRIMARY_URL` 写对没有）。
